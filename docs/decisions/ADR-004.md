# ADR-004 — Grok 4.6 becomes a standing second cross-vendor review leg on Tier-2 diffs

- **Status:** Accepted
- **Date:** 2026-09-02
- **Decider:** Jim, direct (one of eight roadmap decisions taken in his own session; `LOG.md`
  2026-09-02 ~14:00 UTC)

## Question

`ROSTER.md` seated Grok 4.6 as *Research · Panel seat (attacker mandate)*, secrets-free, and said
in so many words *"not a Tier-2 reviewer"*. On 2026-09-02 Jim instructed the build seat to have
Grok review Tier-2 code alongside Gemini 3.7 for a delegation window, which was recorded as a named
deviation. The window is over; the roster and the practice disagree. Which one moves?

## Evidence

Four Tier-2 diffs were reviewed by both legs on 2026-09-02, all from a diff only, with no repo
access and no secrets:

| PR | Gemini 3.7 | Grok 4.6 | What only Grok found |
|---|---|---|---|
| #43 F-5 | CHANGES REQUESTED, 6 | CHANGES REQUESTED, 15 | one racing collision rolled back a whole batch of re-keys; the `COPYUID`'s UIDVALIDITY was discarded (a recreated mailbox reuses UIDs) |
| #44 F-4 part 1 | CHANGES REQUESTED, 6 | CHANGES REQUESTED, 11 | the deletion set was not generation-scoped and the search-all pieces were separately callable — a resurrected UID could be deleted on one observation; `exists: 0` on an unchecked row read as "folder emptied" |
| #45 fix | APPROVE WITH NITS | — | — |
| #47 F-4 part 2 | CHANGES REQUESTED, 5 | CHANGES REQUESTED, 12 | deletion matched rows by id alone; an empty list against a positive EXISTS passed as complete; a short LIST could shrink the attestation universe; approval was not one transaction |

Every Grok finding was re-derived against the tree before adoption; one (#43 L8, range order)
was declined with an RFC citation, the rest were real. The two legs found **different** defects on
every PR. Opus 5's full review of the window (`docs/reviews/2026-09-02-opus5-window-review.md`)
independently recommended settling this row rather than leaving practice and roster apart.

## Decision

1. Grok 4.6 (via the `grok` CLI, `grok -m grok-4.6 --disable-web-search --prompt-file …`) is a
   **standing second cross-vendor review leg on Tier-2 diffs**, alongside Gemini 3.7 via `agy`.
   Both legs run on every Tier-2 PR; their findings are dispositioned on the PR and the raw output
   is preserved under `docs/reviews/`.
2. Its **credential scope does not change**: diffs and inline context only, secrets-free, no repo
   read or write, no tool use during review. The prompt tells it not to use tools; its long-prompt
   "offload" behaviour reads only what the wrapper wrote for it.
3. Its findings are **evidence, not approval**: the author re-derives each one against the tree
   before adopting or declining, with the reason recorded (`03-agents.md` no-self-approval still
   holds — Grok is a reviewer, not an approver).
4. `ROSTER.md`'s Grok row moves from *Research · Panel seat* to *Adversarial review (Tier-2 diffs,
   second leg) · Research · Panel seat*, trust level unchanged at 0 (secrets-free). `TEAM.md`
   position 19's backup text names it as the standing second leg. The canonical
   `~/claude-memory/methodology-v2/ROSTER.md` is Jim's to update; this repo's pinned copy wins here.

## Consequences

- Every Tier-2 PR pays two review rounds (~5–10 minutes each, run in parallel). Worth it on
  deleting or identity-rewriting code; on a Tier-1 PR one leg is enough.
- The xAI safety-record caveat in the roster stays: it governed the trust level (secrets-free),
  which is unchanged, not the seat's usefulness on a diff.
- If Grok's hit rate falls or a finding is ever found to be fabricated and not caught by the
  re-derivation step, this ADR is the thing to revisit.

## Alternatives considered

- **Time-boxed exception** in `EXCEPTIONS.md` — rejected: four-for-four evidence is a decision,
  not a trial.
- **Back to panel-only** — rejected: one leg missed real defects on deleting code three times in a
  day.
