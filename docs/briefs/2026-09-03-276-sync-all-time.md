# SPEC-276 — "All time" sync period, and the `|| 365` that would have eaten it

- **Task:** Let a user sync their whole mailbox (plus 2- and 5-year options) by making `0`
  a legitimate value of `sync_period_days` that means "no date filter" on both providers.
- **Tier:** **1** — touches `services/gmail/syncManager.ts`, `services/gmail/sync.ts`,
  `services/imap/imapSync.ts` and `components/settings/SettingsPage.tsx`; none is on
  `CLAUDE.md`'s Tier-2 list and the Rust IMAP client is untouched. Reversible by revert (no
  schema, no data). Plan in the PR before code; one independent review leg.
- **Base:** `main` @ `eeaa805` (code pin `2d6d52a`). Every citation below was grepped at that pin.
- **Status:** building — branch `f276-sync-all-time`.
- **Source:** upstream avihaymenahem/velo#276 (feature request by the author of upstream PR #275,

- **Effort:** S · ½ day.

## Outcome

The Sync Period dropdown gains "Last 2 years", "Last 5 years" and "All time (entire mailbox)".
Choosing "All time" and running a full resync fetches every message on the server for both
Gmail-API and IMAP accounts. The existing 30/90/180/365 choices behave exactly as before.

## The defect, verified in the fork

1. **A stored `0` is silently turned into 365.** `syncManager.ts:57` and `:98` both read
   `parseInt(syncPeriodStr ?? "365", 10) || 365`. `parseInt("0") === 0` is falsy, so the
   `||` fallback fires for a legitimate zero as well as for `NaN`. Today nothing writes `0`
   (the dropdown at `SettingsPage.tsx:1027-1035` offers 30/90/180/365), so the bug is latent —
   but it is exactly the line that would defeat this feature.
2. **Gmail always filters.** `sync.ts:190-213` unconditionally builds `after:YYYY/M/D` and
   passes it as `q`. `client.ts:167` already omits `q` when it is falsy, so `undefined` is the
   correct "no filter" value.
3. **IMAP always filters, but the Rust side is ready.** `imapSync.ts:577`, `:1010` and `:1165`
   call `computeSinceDate(daysBack)` and pass the string to `imapSearchFolder`. The Rust
   command (`client.rs:1026-1029`, and `:1077-1080` for `sync_folder`) does
   `match since_date { Some(d) => "SINCE d", None => "ALL" }` — so passing `null` is the whole
   IMAP change. `imapSync.ts:589` also applies a per-message cutoff
   (`Date.now()/1000 − daysBack·86400`, `:632 if (msg.date < cutoffDate) continue`), which must
   be disabled for all-time or every old message would be searched, fetched and then dropped.

## Requirements

- **REQ-1** As a user with a long mail history I want Velo to fetch all of it.
  - REQ-1.1 WHEN `sync_period_days` is `"0"` THE SYSTEM SHALL run the Gmail initial sync with
    no `q` filter.
  - REQ-1.2 WHEN `sync_period_days` is `"0"` THE SYSTEM SHALL run every IMAP folder search
    (initial sync, delta sync of a new folder, UIDVALIDITY resync) with `sinceDate = null`,
    which the Rust side already sends as `UID SEARCH ALL`.
  - REQ-1.3 WHEN `sync_period_days` is `"0"` THE SYSTEM SHALL NOT drop fetched IMAP messages
    by date (the per-message cutoff is off).
  - REQ-1.4 The dropdown SHALL offer 730, 1825 and 0 in addition to today's four, with a
    help-text note that "All time" takes longer and uses more disk.
- **REQ-2** As a user I want the existing settings to keep their meaning.
  - REQ-2.1 `parseSyncPeriodDays` SHALL return `0` for `"0"`, `n` for a positive integer
    string, and `365` for `null`, `undefined`, `""`, `"abc"`, `"-5"`, `"1.5"` and `"NaN"`.
  - REQ-2.2 WHEN the value is positive THE SYSTEM SHALL behave exactly as at `eeaa805`
    (existing `sync.test.ts`, `syncManager.test.ts`, `imapSync.test.ts` stay green unchanged).

## Design

- **Current behaviour** — above, with `file:line`.
- **Change**
  - New `src/services/syncPeriod.ts`: `DEFAULT_SYNC_PERIOD_DAYS = 365`, `ALL_TIME = 0`,
    `parseSyncPeriodDays(raw: string | null | undefined): number` (REQ-2.1), `isAllTime(days)`.
  - `syncManager.ts:57`/`:98` → `parseSyncPeriodDays(await getSetting("sync_period_days"))`.
  - `sync.ts` `initialSync`: `q` is `undefined` when `isAllTime(daysBack)` (REQ-1.1).
  - `imapSync.ts`: `sinceDateForDaysBack(daysBack): string | null` used at the three search
    sites (REQ-1.2); `cutoffDate = isAllTime(daysBack) ? 0 : …` (REQ-1.3).
  - `SettingsPage.tsx`: the three options and the note (REQ-1.4).
- **Decision & alternatives** — (a) `0` = all time, the upstream convention, one parser. (b) A
  separate boolean setting `sync_all_time` — two settings to keep consistent, and the dropdown
  is the natural single control. (c) A sentinel like `-1` — no clearer and needs the same
  parser. (a).
- **Data / schema** — none; the setting is a string in `settings` (default `'365'`,
  `migrations.ts:167`).
- **Failure modes** — if the parser is wrong the worst case is the old one: a period of 365. If
  the IMAP cutoff were left on, all-time would fetch everything and store only the last year —
  REQ-1.3's test guards it. A very large mailbox is slow and large on disk — by choice, stated
  in the UI.
