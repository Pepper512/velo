## Findings

### 1. MEDIUM — `connection_tests.rs` `run_cancellable` / `cancel`

**Concern:** Register happens after `tokio::spawn`. Cancel is a separate, synchronous command.

**Scenario:** `connection_test_cancel(id)` runs before `register(id, handle)` — easy if the cancel IPC is scheduled first (sync command vs async test command), on unmount immediately after Test, or if Cancel is pressed in the same frame the invokes are still queued.

**Consequence:** Cancel returns `false`, the task then registers and runs the full ladder (up to ~90 s) with credentials on the wire. The webview is idle (generation already bumped), so the failure is silent. This is the REQ-2 hole.

**Fix:** Insert a tombstone *before* spawn. `cancel` either aborts a live `AbortHandle` or marks the id pre-cancelled. After spawn, if the slot is already cancelled, `handle.abort()` immediately.

```rust
enum Slot { Pending, Live(AbortHandle), Cancelled }

// start: insert Pending, spawn, then replace with Live or abort if Cancelled
// cancel: Pending → Cancelled (return true); Live → abort; missing → false
```

### 2. MEDIUM — `connectionTestRun.ts` `start`

**Concern:** `start` does `inFlight = new Set([imapId, smtpId])`. It does not cancel the previous ids.

**Scenario:** Double-click Test (second click before the Testing/Cancel row paints), or any caller of `start` without `cancel` — including the re-test case the unit test already writes.

**Consequence:** Generation correctly drops the stale *UI* result. The old IMAP/SMTP tasks keep running until timeout. Two extra credentialed attempts. REQ-2 fails on supersede the same way UI-only cancel would have.

**Fix:** At the top of `start`, snapshot and abort the previous set (same IPC as `cancel`, without waiting), then mint the new ids.

```ts
const stale = [...inFlight];
generation += 1;
// mint, assign inFlight, then:
void Promise.all(stale.map((id) => cancelConnectionTest(id).catch(() => false)));
```

### 3. MEDIUM — `AddImapAccount.tsx` `mapSecurity`

**Concern:** Drive-by on the credential path. Unknown values now become `"none"` instead of being passed through.

**Scenario:** UI state is already `"tls"` (the Rust name), or any value other than `"ssl"` / `"starttls"` (empty, `"plain"`, `"STARTTLS"`). Old code sent `"tls"` through. New code sends `security: "none"`.

**Consequence:** The test connects in plaintext and ships the password / OAuth token. Wrong for a cancel PR; fail-open if the form ever stores the Rust-side name.

**Fix:** Revert to the old mapping, or map unknown to an error and refuse to test. Do not default to `"none"`.

### 4. MEDIUM — `connection_tests.rs` tests / `smtp_test_connection`

**Concern:** Abort is proven only for `tokio::sleep` and for IMAP `security: "none"` waiting on a greeting. SMTP is wrapped the same way but never cancelled against a socket.

**Scenario:** `smtp_client::test_connection` uses blocking lettre, `spawn_blocking`, or native-tls that does not yield. `AbortHandle` does not interrupt that.

**Consequence:** IMAP Cancel returns in <1 s; SMTP still sits on lettre’s timeout. `Promise.all` in `start` waits for both. The form can look idle (generation) while the SMTP attempt continues.

**Fix:** Mirror the silent-`TcpListener` test for SMTP. If it does not abort in <1 s, the SMTP path is not cancellable and needs an async transport (or a token through the connect). Do not ship REQ-2 as done for both commands until that test exists.

### 5. LOW — `connection_tests.rs` `run_cancellable`

**Concern:** No `Drop` guard. `remove(id)` runs only after `handle.await`.

**Scenario:** The command future is dropped (webview teardown, runtime shutdown) between `register` and `remove`. Dropping `JoinHandle` *detaches*, it does not abort.

**Consequence:** Registry leak of one `AbortHandle` and an orphaned connect that still holds the password in the task. Same class as a timeout today, plus a stuck map entry.

**Fix:** A guard that `remove`s on drop, and `handle.abort()` if the outer future goes away before join.

### 6. LOW — `connection_tests.rs` `register`

**Concern:** `HashMap::insert` overwrites. The previous handle is dropped, not aborted.

**Scenario:** Two tests with the same `testId` (malicious/injected JS; or the 2⁻⁵³ `imapId === smtpId` case).

**Consequence:** Cancel aborts only the latest. The first runs to timeout. Registry never knew about it.

**Fix:** On insert, `abort()` the displaced handle (or reject a duplicate id).

### 7. LOW — `AddImapAccount.tsx` modal Cancel vs `useEffect` cleanup

### 8. LOW — `connection_tests.rs` panic path / tests

**Concern:** Panic of `work` is mapped to `Err(format!("connection test failed: {join}"))` and the entry is removed. Unittest never panics.

**Scenario:** A panic in connect/TLS. A wrong impl that `remove`s only on `Ok` still passes the current suite.

**Consequence:** Leaked handle; panic text forwarded to the webview.

**Fix:** One test that `panic!`s inside `work`, asserts `in_flight() == 0`, and maps to an error. Prefer a fixed string, not `{join}`.

## Review items 1–4, answered

**Rust abort.** For the IMAP plaintext greeting wait, yes: abort drops the task at `.await`, the `TcpStream` drops, the socket goes with it. Mid-LOGOUT is the same as today’s timeout (no LOGOUT). TLS handshake / lettre SMTP are the same *if* they are cooperative async; that is not shown. `spawn_blocking` or blocking lettre survives abort. Poison: recovered via `into_inner` — good. Panic: joined and removed, untested. Duplicate id: last handle wins. Cancel-before-register: miss (finding 1).

**Exposure.** `connection_test_cancel` can only `abort()` a handle in this map. Return is `bool`. No config, host, or password. It cannot touch sync/fetch/pool. Brute-forcing 53-bit ids is not a useful probe. XSS can already call `imap_test_connection`; this adds “stop that task,” not a new data leak. Without `testId`, `run_cancellable` awaits inline — other callers are unchanged. `State<ConnectionTests>` is not a JS argument.

**TS run.** Stale delivery is blocked by `mine !== generation` (checked *before* `inFlight.delete`, so a stale settle cannot punch a hole in a newer set). Fresh results after a clean `start` are delivered. Cancel copies ids before clearing, so it will not cancel a *newer* run’s ids if `start` happened during `await Promise.all(cancel…)`. `isRunning` is false after that clear even while Rust is still unwinding — fine, the form does not use it. Unmount: cleanup calls `cancel()` (generation bump is sync). Modal Cancel is not wired except via unmount (finding 7). Re-test during cancel-await is OK for ids; re-test *without* cancel orphans (finding 2).

**Wire.** `testId: null` → serde `Option<u64>` = `None`. Omitted key is Tauri’s usual missing-`Option` = `None` (the spec’s claim); the wrappers do not rely on that because they always send `null`. `newTestId` is in `1..=2⁵³−1` (`MAX_SAFE_INTEGER`), so JSON number → `u64` is exact. `??` correctly keeps `0` if anyone passed it.
