**APPROVE WITH NITS**

The three production lists are the RFC 3501 form, attributes are unchanged, and response parsing should not shift. The guard matches today’s one-line call style and will not catch the next site if it is formatted like ordinary Rust.

### Findings

1. **MEDIUM** — `src-tauri/src/imap/client.rs`, `fetch_attribute_arguments`  
   **Concern:** Line-oriented scan misses a `.uid_fetch(` whose arguments are not on the same line.  
   **Scenario:** Next site is written (or rustfmt-wrapped) as
   ```rust
   session.uid_fetch(
       &uid_set,
       "UID FLAGS INTERNALDATE BODY.PEEK[]",
   )
   ```
   The `.uid_fetch(` line has no comma, so the loop `continue`s. `sites.len() >= 5` still holds from the five one-line calls.  
   **Consequence:** REQ-1.3 is not met; the regression this PR exists to prevent can land green.  
   **Fix:** Scan the file as one string (e.g. `(?s)\.uid_fetch\s*\((.*?)\)`), take the second argument across newlines, and keep the unknown-ident panic.

2. **MEDIUM** — `src-tauri/src/imap/client.rs`, `fetch_attribute_arguments`  
   **Concern:** Same-line `.await` / trailing comma / comment after the call is parsed as the attribute ident.  
   **Scenario:** `.uid_fetch(&uid_str, FETCH_BODY).await` — after the comma, `second` is `FETCH_BODY).await`; `trim_end_matches(')')` does not strip, match arm misses, test panics. Same for `FETCH_FULL),` or `FETCH_FULL) // sync`.  
   **Consequence:** A style-only edit fails CI; people then weaken or delete the guard.  
   **Fix:** After the comma, take an identifier (`[A-Z0-9_]+`) or a `"..."` literal; ignore `.await`, commas, comments.

3. **LOW** — `src-tauri/src/imap/client.rs`, `every_multi_attribute_fetch_list_is_parenthesised`  
   **Concern:** “Multi” is “contains a space after stripping wrapping parens.” That is not RFC `fetch-att`.  
   **Scenario:** `.uid_fetch(&uid, "BODY.PEEK[HEADER.FIELDS (FROM TO)]")` — one legal `fetch-att`, has spaces, no wrapping parens → assertion fails.  
   **Consequence:** A correct single-attribute fetch is rejected, or someone parenthesises only to silence the test.  
   **Fix:** Treat as multi only when there are two or more top-level `fetch-att` tokens (split on spaces not inside `[]`).

4. **LOW** — `src-tauri/src/imap/client.rs`, `fetch_attribute_arguments` / `raw_fetch_messages`  
   **Concern:** Guard is `.uid_fetch(` in this file only. REQ-1.1 is every multi-attribute `FETCH` / `UID FETCH`.  
   **Scenario:** `session.fetch(seq, "UID FLAGS BODY.PEEK[]")`, or a new raw write like the diagnostic (`a3 UID FETCH {} …`) with a bare list.  
   **Consequence:** Strict servers drop the body again; test stays green.  
   **Fix:** Also match `.fetch(` and command strings containing `UID FETCH` / ` FETCH `; resolve `{FETCH_*}` in `format!` strings the same way.

5. **NIT** — `src-tauri/src/imap/client.rs`, `FETCH_FULL`  
   **Concern:** Name collides with RFC 3501 macro `FULL` (`FLAGS INTERNALDATE RFC822.SIZE ENVELOPE BODY`), which this string is not.  
   **Scenario:** A later change swaps in `"FULL"` or adds `ENVELOPE` because the name says so.  
   **Consequence:** Different payload, different parse path, possible `has no body` if `BODY` is not `BODY.PEEK[]`.  
   **Fix:** Rename e.g. `FETCH_UID_FLAGS_INTERNALDATE_BODY`.

6. **NIT** — `src-tauri/src/imap/client.rs`, `every_multi_attribute_fetch_list_is_parenthesised`  
   **Concern:** `>= 5` only blocks an empty scan.  
   **Scenario:** One one-line site is deleted and a multiline bare list is added; count remains 5.  
   **Consequence:** Complements finding 1.  
   **Fix:** After a newline-tolerant scan, assert exact production count (or exact line list), excluding comments.

No HIGH. Parenthesised lists match §6.4.5 (`"(" fetch-att *(SP fetch-att) ")"`). `FETCH_BODY` correctly stays a single `fetch-att`. The FETCH *response* is always a parenthesised att-list plus `{n}` literals for `BODY[]`; PEEK is request-only. The `has no body` warn fires when the parsed fetch has no body bytes — it should fire less on Stalwart, not more. `extract_literal_size` / literal continuation are unchanged. Diagnostic `a3 UID FETCH {} {FETCH_FULL}` is the same bytes as before. `FETCH_BODY` at the two single-attribute sites is not a behaviour change.

### Coverage gaps

- **Wire bytes:** mock/recording session: `uid_fetch("1:3", FETCH_FULL)` sends `UID FETCH 1:3 (UID FLAGS INTERNALDATE BODY.PEEK[])` and not the bare list. Same for `FETCH_UID_FLAGS_BODY` and `FETCH_BODY`.
- **Stalwart shape:** on bare list, server returns `* n FETCH (UID 1)` only → existing `has no body` path; on parenthesised list, same UID with `BODY[] {…}` → body present. That is issue 241.
- **Parser with all atts present:** one fetch that has `UID`, `FLAGS`, `INTERNALDATE`, and a `BODY[]` literal (the Stalwart-after-fix case). Today that path is only known-good on Dovecot/Gmail.
- **Guard fixtures (unit the scanner, not only live source):** (a) multiline bare list must fail; (b) `.uid_fetch(&uid, FETCH_BODY).await` must pass; (c) `BODY.PEEK[HEADER.FIELDS (FROM TO)]` must pass as a single att; (d) comment `// .uid_fetch(set, "UID FLAGS")` must be ignored; (e) unknown ident `q` must fail closed.
- **Non-`uid_fetch`:** `session.fetch` and a raw `UID FETCH` write with a bare list must fail the guard (or a sibling test).
- **Optional live:** `fetch_messages` against the Dovecot harness after the change (spec task 3) — confirms parenthesised form still yields bodies on a tolerant server.

### What is good

Constants sit next to the RFC rule; all three multi-item sites and the diagnostic share one string, so the attribute set cannot drift between sync and the raw probe. Single-attribute `BODY.PEEK[]` is left unparenthesised. Unknown second arguments panic (fail closed) instead of being skipped. The snapshot test pins REQ-1.2 (no att added/dropped). CLAUDE.md records Stalwart vs Dovecot/Gmail. No user-controlled bytes in the command; UID sets still go through `wire::validate_uid_set` on the raw path. Rollback is a revert.
