### Findings

1. **MEDIUM** — `src-tauri/src/ai_fetch.rs` `tests` / `src/services/ai/rustFetch.test.ts` `isAllowedAiUrl`  
   **Concern:** The accept/refuse tables never exercise the URL shapes that break host-string filters. The live code uses WHATWG parse + `IpAddr::is_loopback()`, so these likely behave today; the tests would not notice if that stopped being true.  
   **Scenario:** A later change compares the raw or un-normalised host to `"localhost"` / `"127."` / a dotted private-IP list.  
   **Consequence:** `http:` to a non-loopback address (or a false sense of coverage) ships with a green suite.  
   **Fix:** Add the same rows on **both** sides (TS must not accept anything Rust refuses). Minimum:

   | URL | Expected |
   |---|---|
   | `http://[::ffff:10.0.0.1]/` | refuse |
   | `http://[::ffff:169.254.169.254]/` | refuse |
   | `http://[::ffff:127.0.0.1]/` | refuse (not `::1`; spec’s loopback list) |
   | `http://0x0a000001/` (→ `10.0.0.1`) | refuse |
   | `http://0177.0.0.1/` / `http://0x7f.0.0.1/` / `http://127.1/` / `http://2130706433/` (→ `127.0.0.1`) | accept |
   | `http://0127.0.0.1/` (octal `0127` = `87.0.0.1`) | refuse |
   | `http://0.0.0.0/` and `http://[::]/` | refuse |
   | `http://[fe80::1]/`, `http://[fd00::1]/` | refuse |
   | `http://localhost./` | refuse (or document and pin the opposite) |
   | `http://localhost%2eexample.com/` | refuse |
   | `http://127.0.0.1%0d%0a/` / `http://127.0.0.1 ` (internal whitespace) | refuse |
   | `https://:@host.example/v1` | refuse (userinfo present) |

2. **MEDIUM** — `src-tauri/src/ai_fetch.rs` `is_loopback_host`  
   **Concern:** Loopback is only `localhost` (exact), `IpAddr::is_loopback()`, and the TS side a `127.x.x.x` regex + `::1`. IPv4-mapped IPv6 is **not** loopback in Rust (`Ipv6Addr::is_loopback` is only `::1`), which is the safe direction, but it is untested. `0.0.0.0` / `[::]` are unspecified, not loopback; connecting to them often hits local services.  
   **Scenario:** `http://0.0.0.0:8080` or `http://[::ffff:10.0.0.1]/` after a “treat mapped/unspecified as local” tweak.  
   **Consequence:** http to a non-loopback (or to every local bind) while tests stay green.  
   **Fix:** Keep current refusals; pin them with finding 1. Do not use `to_canonical()` / `is_unspecified()` / `is_private()` as a substitute for the spec list.

3. **LOW** — `src-tauri/src/ai_fetch.rs` `fetch_with_limits`  
   **Concern:** `status.is_redirection()` is the whole 300–399 class.  
   **Scenario:** A 304 (or 300) from `GET /models`.  
   **Consequence:** A non-redirect 3xx is reported as “redirects are not followed”; TS’s 304 null-body path is dead. `Policy::none()` does **not** follow 307/308; `Location` on 2xx is not followed and is not in the response allow-list.  
   **Fix:** Refuse 301/302/303/307/308 (and 300 if you want); pass 304 through with an empty body.

4. **LOW** — `src-tauri/src/ai_fetch.rs` `fetch_with_limits` (response headers) + OpenAI SDK retries  
   **Concern:** `retry-after` is returned verbatim. The 120 s cap applies to the Rust call, not to the SDK sleep after a 429.  
   **Scenario:** Hostile or compromised endpoint returns `429` + `Retry-After: 86400` (or an HTTP-date a year out). SDK default `maxRetries` is 2, and each retry re-POSTs the prompt (mail).  
   **Consequence:** UI/task stuck far beyond 120 s; mail content sent three times. A huge JSON is bounded by 8 MiB on the wire; a nested-JSON bomb inside that cap is residual. `String::from_utf8_lossy` will not resurrect a second interpretation of invalid UTF-8; it can only break JSON, which is fine.  
   **Fix:** Clamp `retry-after` (e.g. ≤ 60 s) or drop it; set `maxRetries: 0` or `1` on the custom client; reject non-UTF-8 bodies instead of lossy-converting.

5. **LOW** — `src-tauri/src/ai_fetch.rs` `fetch_with_limits`  
   **Concern:** Response body is capped; request body is not.  
   **Scenario:** Compromised renderer (or a huge thread) POSTs tens of MB to any allowed URL.  
   **Consequence:** Bandwidth/memory DoS through a command that is otherwise careful. Header values are similarly uncapped; `HeaderValue` will reject CR/LF, so request-header injection into reqwest is not the issue.  
   **Fix:** Cap request body (and optionally header value length) at the same 8 MiB, before `send`.

6. **LOW** — `src/components/settings/SettingsPage.tsx` Test Connection `catch`  
   **Concern:** Success path uses `testConnection()` → `describeError`. The `catch` assigns `err.message` / `String(err)` with no redaction.  
   **Scenario:** `testConnection` throws (invoke wrapper, zod “malformed”, unexpected SDK throw) with a body that echoed a key.  
   **Consequence:** Key-shaped material in the inline failure text and the `title` tooltip.  
   **Fix:** Run that `catch` through `describeError` as well.

7. **LOW** — `src-tauri/src/ai_fetch.rs` `ai_fetch` (IPC surface)  
   **Concern:** Any script in the webview can `invoke("ai_fetch", …)` with any URL that passes the rule. Email HTML in a scriptless sandbox cannot. Reach is **not** wider than plugin-http (`https://*` + `http://*`): this door is stricter on `http:` (loopback only), does not follow redirects, and cannot set `Host`/`Cookie`. It **is** a new always-on POST primitive that does not require the user to enable Custom.  
   **Scenario:** XSS → `POST http://127.0.0.1:631` (CUPS) or `https://attacker.example` with stolen `authorization` and mail text.  
   **Consequence:** Same class as plugin-http XSS, narrower destinations, still local-http POST. Compromised renderer already has `db_tx_*` / IMAP.  
   **Fix:** Optional defence-in-depth: require the URL’s origin to match the saved `custom_base_url`, or add an explicit capability instead of riding `core:default`. Not required to match decision 2; document as residual if you skip it.

8. **NIT** — `src/services/ai/rustFetch.ts` `isAllowedAiUrl` vs `validate_ai_url`  
   **Concern:** TS is stricter on some forms (`http://127` → `0.0.0.127` is loopback in Rust, rejected by the `127.` first-octet regex) and possibly looser on empty-password userinfo (`https://:@host`: browser `username`/`password` are `""`, Rust `password().is_some()`). Pre-check must not be more permissive.  
   **Scenario:** User saves a URL the UI accepted; first `ai_fetch` fails. Or empty-password userinfo is saved and later a Rust change starts sending Basic.  
   **Fix:** Refuse if `url.href` contains `@` before the first `/` after the host, or if `password` is non-null in any form. Mirror `http://127` as refuse on both, or accept on both.

9. **NIT** — `src/services/ai/rustFetch.ts` `rustFetch`  
   **Concern:** Body is taken only from `init.body`, not from a `Request` input. Abort is checked only before `invoke`, not cancelled in flight.  
   **Scenario:** SDK passes a `Request` with the JSON body (body dropped → empty POST). User navigates away; Rust still runs to 120 s.  
   **Fix:** Read `fromRequest` body when `init.body` is absent; pass a timeout/cancellation if you ever wire `signal` through. Add a test: `rustFetch(new Request(url, { method: "POST", body: "{}" }))`.

10. **NIT** — `src/services/ai/providers/customProvider.ts` / request header allow-list  
    **Concern:** Spec’s four request headers are enough for OpenRouter/DeepSeek chat completions. Dropped on purpose: `OpenAI-Organization`, `OpenAI-Beta`, `x-api-key` / `api-key` (Azure), `HTTP-Referer` / `X-Title` (OpenRouter ranking). Response `retry-after-ms` is also dropped. Nothing on the allow-list should come off (`authorization` is required; `user-agent` is harmless).  
    **Scenario:** Azure-style custom URL silently never authenticates because `api-key` is stripped.  
    **Fix:** Leave as specified; mention Azure in the card help. Do not add `Cookie`, `Host`, or `Referer`.

### What is good

- Decision 2 is actually implemented: `https` any host, `http` only after `is_loopback_host`, userinfo rejected, no host rejected; CSP and capabilities untouched.
- `redirect::Policy::none()` plus an explicit 3xx error that includes only the status — 302 test pins that `Location` never appears in the error; reqwest will not follow 307/308 under `Policy::none()`.
- Request/response header allow-lists are case-insensitive and tested in both directions (`Host` / `Cookie` / `set-cookie` / stainless headers dropped).
- `reqwest::Error::without_url()`, the query-echo test, and logs of `{method, host, status}` only — the key is not put on the URL by the provider.
- 8 MiB cap is applied from `Content-Length` **and** from chunk accumulation; 120 s timeout on the client.
- TS `zod` on the invoke result before `new Response`; 204/205/304 null body; non-string bodies refused before IPC.
- No silent `localhost:11434` default; `NOT_CONFIGURED` without a base URL; key optional with an explicit placeholder.
- `custom` is configuration, not an interface change on every provider; model output still goes through `createOpenAICompatibleProvider`.
