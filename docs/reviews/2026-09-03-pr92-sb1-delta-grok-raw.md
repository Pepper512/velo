- **Finding 1 (hover shadow):** Dropping `box-shadow: none` from `.reduce-motion .hover-lift:hover:not(:active)` stops the reduce-effects hover rule from zeroing shadow. `transform: none` still cancels the lift. Comment-only Settings path tweak is harmless.

- **Finding 3 (backdrop):** `.reduce-motion .backdrop-animate` now sets `animation: none`, `backdrop-filter: none`, `-webkit-backdrop-filter: none`, and the solid `background-color`. Explicit `none` covers a static blur on `.backdrop-animate`, not only keyframe blur; the prefix covers Safari.
- **Finding 4 (await `platform()`):** `await (await load()).platform()` plus `platform: () => string | Promise<string>` is correct hardening; `await` on a sync `string` keeps existing macos/windows/ios stubs valid.
- **Pop-outs:** `try/catch` still maps plugin-import / `platform()` throws to `"unknown"`; stored-valid pop-outs still resolve from `stored` (see reliance below).

Outside the delta this review relies on: `resolveReduceEffects` treats unrecognized `stored` as missing and falls through to `input.platform === "linux"` (only the last line is in the diff); a recognized stored boolean wins even when `platform` is `"unknown"`; `restoreReduceMotion` is a boolean setter that applies `false` to the UI store/DOM class (and does not require `persisted`); `import("@tauri-apps/plugin-os")` throws in pop-outs rather than hanging; `.backdrop-animate` blur is on that element (or its animation), not a child/`!important`/higher-specificity rule; `.hover-lift:hover` does not change `box-shadow` (R2-1).
