2. Findings:

[H] F-01 — `src/components/email/ThreadView.tsx:213-215` — From-alias resolution is clobbered by Composer's own post-render effect. In `ThreadView.tsx:202-215`, `handleInstantIntro` opens the composer via `openComposer({ mode: "replyAll", to: instantIntro.to, cc: instantIntro.cc, ... })` and then synchronously executes `const from = resolveFromAddress(aliases, lastMessage.to_addresses, lastMessage.cc_addresses); if (from) useComposerStore.getState().setFromEmail(from.email);`. As the author's comment on line 212 acknowledges (*"The composer picks the From alias from the reply's To/Cc, and the intro has removed me from both"*), `<Composer />` contains its own effect that resolves the From alias from `to` and `cc`. Because `openComposer` updates Zustand store state, `<Composer />` renders and its effect executes during the subsequent commit phase — running *after* `handleInstantIntro`'s synchronous `setFromEmail` call. Since `instantIntro.to` and `instantIntro.cc` have had the account's own addresses and aliases stripped per REQ-1.1, Composer's effect finds no matching alias in `to`/`cc` and falls back to resetting `fromEmail` to the account's primary address. Replying to an introduction sent to a send-as alias thus silently discards the resolved alias and sends from the primary account instead. Note: this relies on `<Composer />` effect behavior outside the immediate diff, as attested by line 212.

[M] F-02 — `src/components/email/ThreadView.tsx:70-81, 191-196` — Asynchronous alias loading causes an initial-render race condition and retains stale aliases across account switches. In `ThreadView.tsx:70-81`, `aliases` is initialized to `[]` via `useState<SendAsAlias[]>([])` and loaded asynchronously on mount via `getAliasesForAccount(activeAccountId)`. Until the asynchronous SQLite query resolves, `aliases` remains empty, meaning `ownAddresses` on line 191 contains only `[activeAccount.email]`. If the user presses `b` or views the button immediately upon opening a thread sent to or from a send-as alias: (1) the alias is not recognized as an own address, leaving the alias in `instantIntro.to`/`cc` and falsely enabling the button on single-recipient emails (allowing the user to reply to their own alias); and (2) if the last message was sent from an alias, `own.has(introducer)` evaluates to false, failing to disable the action per REQ-1.3. Additionally, when `activeAccountId` changes, `aliases` is not reset to `[]` in the effect cleanup or before fetching, leaving stale aliases from the previous account mixed with the new account's email while the new query is in flight.

[L] F-03 — `src/components/email/ThreadView.tsx:449` — The generic unavailability reason "Nobody to introduce you to" is shown when the last message is the user's own. In `ThreadView.tsx:449`, `introUnavailableReason` is unconditionally passed as `instantIntro ? null : "Nobody to introduce you to"`. When `buildInstantIntro` returns `null` because the introducer is one of the user's own addresses (`own.has(introducer)` at `instantIntro.ts:101`), the action bar button is disabled with the tooltip "Nobody to introduce you to". Even on a multi-party thread with other recipients, the tooltip misleadingly asserts that nobody else is on the thread, rather than explaining that the user was the last sender (as specified in REQ-1.3: *"the introducer is one of the account's own addresses (the last message is mine — nobody to thank)"* and documented in `helpContent.ts:330`).

[N] F-04 — `src/services/composer/instantIntro.ts:79` — `introducerFirstName` preserves surrounding punctuation or quotes from `from_name`. In `instantIntro.ts:79`, `fromName?.trim().split(/\s+/)[0]` splits purely on whitespace. If `from_name` contains quoted display names (e.g. `"Alice" Smith`) or trailing punctuation from inverted formats (e.g. `Smith, Alice`), `first` retains the leading quote or comma (e.g. `"Alice"` or `Smith,`), which is interpolated directly into `<p>Thanks ${escapeHtml(introducerName)}, moving you to Bcc.</p>`. While `escapeHtml` prevents injection, stripping leading/trailing non-word punctuation would produce a cleaner greeting.
