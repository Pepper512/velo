## Numbered Findings

### 1. HIGH — `src/components/accounts/AddImapAccount.tsx`: `mapSecurity`
* **Concern:** `mapSecurity` drops `"tls"` and falls through to `"none"`, causing secure connections configured with `"tls"` to connect unencrypted.
* **Exact scenario:** When `form.imapSecurity` or `form.smtpSecurity` is `"tls"` (e.g., loaded from a preset, autoconfig, or existing account config), `mapSecurity("tls")` checks `security === "ssl"` (false) and `security === "starttls"` (false), and returns `"none"`.
* **Consequence:** The connection test runs over plaintext without TLS, sending credentials in the clear and failing on servers that require TLS on port 993/465.
* **Fix:**
```ts
function mapSecurity(security: string): ImapConfig["security"] {
  if (security === "ssl" || security === "tls") return "tls";
  if (security === "starttls") return "starttls";
  return "none";
}
```

### 2. MEDIUM — `src/components/accounts/connectionTestRun.ts`: `start`
* **Concern:** A re-test or superseded run orphans previous in-flight tasks in Rust without cancelling them.
* **Exact scenario:** A caller invokes `start()`, and while it is running, `start()` is invoked again. `start()` overwrites `inFlight = new Set([imapId, smtpId])` with the new IDs without cancelling the previous run's IDs.
* **Consequence:** The previous run's spawned tasks keep running in Rust for up to ~90 s (violating REQ-2: *"a cancelled attempt to actually stop"*). Because their IDs were overwritten in `inFlight`, subsequent clicks on "Cancel test" will only cancel the newest run, leaving the orphaned tasks impossible to abort.
* **Fix:** Cancel existing in-flight tests before replacing `inFlight`:
```ts
if (inFlight.size > 0) {
  const staleIds = [...inFlight];
  void Promise.all(staleIds.map((id) => cancelConnectionTest(id).catch(() => false)));
}
```

### 3. MEDIUM — `src-tauri/src/connection_tests.rs`: `run_cancellable` & `ConnectionTests::cancel`
* **Concern:** Race condition if `connection_test_cancel` IPC executes before `run_cancellable` registers the task handle.
* **Exact scenario:** The webview invokes `imap_test_connection` and immediately invokes `connection_test_cancel` (e.g., fast modal close / unmount or double-click). Tauri dispatches IPC commands concurrently across worker threads. If `connection_test_cancel` runs first, `tests.cancel(id)` finds no registered handle and returns `false`. `run_cancellable` then executes, registers the handle, and awaits the 90 s test.
* **Consequence:** The cancel request is lost; the test runs for its full timeout in the background despite the user having cancelled.
* **Fix:** Track cancellation tombstones in `ConnectionTests`. If `cancel(id)` is called before `register(id)`, record `id` in a cancelled set; in `register(id, handle)`, if `id` is already marked cancelled, immediately abort the handle.

---

### 4. LOW — `src-tauri/src/connection_tests.rs`: `tests::a_real_imap_test_against_a_silent_server_is_cancelled_within_a_second`
* **Concern:** The test does not verify that the socket was actually closed by the abort.
* **Exact scenario:** The test's listener accepts the connection and sleeps 5 s without inspecting the stream. The test passes as long as `run.await` returns `Err("cancelled")` within 1 s.
* **Consequence:** An implementation that aborts the outer join handle but leaks the underlying socket/thread would pass this test.
* **Fix:** In the listener thread, read from `stream` after client cancellation and assert that it returns 0 bytes (`Ok(0)`, EOF / socket closure).

---

### 5. LOW — `src/services/imap/tauriCommands.test.ts`: `SMTP Tauri commands`
* **Concern:** Missing test coverage for `smtpTestConnection` forwarding `testId`.
* **Exact scenario:** `tauriCommands.test.ts` tests `imapTestConnection` passing a numerical `testId`, but only tests `smtpTestConnection` with `testId: null`.
* **Consequence:** A regression in `smtpTestConnection` argument forwarding would not be detected.
* **Fix:** Add a unit test verifying `smtpTestConnection(testSmtpConfig, 12345)` calls `invoke` with `{ config: testSmtpConfig, testId: 12345 }`.

---

### 6. NIT — `src/components/accounts/connectionTestRun.ts`: `isRunning`
* **Concern:** Unused interface method.
* **Exact scenario:** `AddImapAccount.tsx` maintains its own UI state via `imapTest.state` and `smtpTest.state` and never inspects `testRun.current.isRunning()`.
* **Consequence:** Dead interface surface.
* **Fix:** Either use `isRunning()` in `AddImapAccount` to guard `testBothConnections` against duplicate concurrent invocation before React state updates, or remove it.

## Questions

## What Is Good

1. **Clean cancellation abstraction:** Aborting at the `tokio::spawn` task boundary cleanly drops inner futures (TCP connect, TLS handshake, LIST) and drops the sockets without needing invasive `CancellationToken` plumbing across the client libraries.
2. **Strict exposure control:** `ConnectionTests` contains only `AbortHandle`s and no credentials, hosts, or configs. The cancel IPC accepts only a `u64` and returns `bool`, preventing information leakage.
3. **Poisoning resilience:** `lock()` safely uses `.unwrap_or_else(|poisoned| poisoned.into_inner())` to avoid cascading panics if a thread panics while holding the lock.
4. **Generation counter in TS:** The generation counter prevents race conditions and ensures late results from aborted or superseded tests are dropped and cannot corrupt form state.
5. **Lifecycle cleanup:** Wiring `useEffect(() => () => { void testRun.current.cancel(); }, [])` guarantees that closing or unmounting the modal cancels active network attempts in the backend.
6. **Wire compatibility:** `Option<u64>` handles omitted fields and `testId: null` identically as `None`, preserving backward compatibility for callers without an ID. Safe 53-bit integers deserialize cleanly into `u64` without precision loss.
